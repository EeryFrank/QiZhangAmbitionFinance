## 后续：插件与模组桥接

以下均为计划，不是当前已注册或已测试的兼容层：

| 目标 | 计划内容 | 验收前需要解决 |
| --- | --- | --- |
| Vault Economy | 提供 Bukkit 侧经济服务适配 | 账户语义、整数货币与小数请求策略、主线程切换、幂等/异常映射、服务注册与卸载 |
| EconomyShopGUI | 接入核心余额并定义商店定价归属 | 避免两套动态价格互相覆盖，验证扣款/发货失败及退单 |
| QuickShop 及其维护分支 | 玩家商店交易接入 | 确认具体版本 API、容器物品交付、离线账户、税费与失败恢复 |
| LuckPerms 等权限插件 | 通过现有 resolver 接入明确权限结果 | 生命周期、缓存、继承规则、UUID 拒绝优先和线程安全；当前不能只配置节点就宣称生效 |
| Lightman's Currency | 实物货币或账户互通方案 | 货币发行来源、面额/组件、兑换率、重复兑换与跨账本事务；不承诺直接识别为本服铜银金币 |
| 更多常用商店/任务/领地模组 | 使用 Java API 或明确桥接模块 | 按具体版本验证，不靠物品名称或相似接口判定兼容 |

核心不应依赖任何一家第三方商店才能启动；桥接模块应明确可选依赖、版本边界和失败策略。付费传送采用足额先预扣、确定失败未移动则退款、真实成功后核验提交；不能以客户端“显示成功”代替服务端结果，结果不明时保留待核实收据。

## 后续：其他版本与服端

NeoForge 其他 Minecraft 版本、独立 NeoForge 服务端、其他混合核心、Fabric、Forge 和纯 Bukkit/Paper 都需要单独评估、构建和运行矩阵。它们不是修改 metadata 版本号即可兼容；注册表、组件、网络、线程和存档接口都可能不同。

每一新增组合至少应取得：官方依赖版本依据、隔离编译、真实启动、玩家连接与基本交易、持久化重启、权限边界及异常路径证据。老服迁移必须保留货币 ID 和账本含义，必要时提供显式迁移工具，不自动改写生产存档。

跨整合包价格配置按独立 profile 管理，重新导出实际物品/配方/标签并生成对应证据。本服 7,246 项快照不能代表其他模组组合，也不能把运行时补录的保守参考值称为已人工审核的通用价格库。
